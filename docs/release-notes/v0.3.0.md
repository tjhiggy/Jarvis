# Jarvis v0.3.0 Platform Core

Release date: 2026-08-10

## What changed

Jarvis v0.3.0 establishes the shared platform layer beneath the MuthaShip
community features. It adds module and interaction contracts, authorization
boundaries, feature flags, aggregate command metrics, audit metadata, provider
readiness, and the local-first Command Deck health surface.

The repository now also uses native GitHub automation for Project field sync
and Discussion intake. Discussion ideas remain human-reviewed; accepting one
creates a normal backlog Issue. Jarvis itself does not write to GitHub.

## Operator actions

1. Back up the SQLite database before deployment.
2. Deploy the tagged commit and restart the single Jarvis process.
3. Run the documented admin-console and Discord smoke checks.
4. Confirm `/status`, `/config`, `/engagement status`, and `/engagement metrics`
   report the expected version, database health, and aggregate metrics.
5. Record the deployment result on the release and move verified Phase 0 work
   to Released on the Jarvis Delivery Board.

## Safety and limitations

- No server settings, moderation actions, GitHub writes, or arbitrary role
  grants are introduced by this release.
- Metrics contain aggregate, server-scoped metadata only. They do not retain
  secrets, full message content, or provider credentials.
- The Command Deck is local-first and read-only. Safe configuration writes are
  a later Admin Console milestone.

## Verification

The release candidate must pass the repository test, build, documentation, and
diff gates plus the production smoke checklist before it is considered fully
shipped.
