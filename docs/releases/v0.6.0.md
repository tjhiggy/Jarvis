# Jarvis v0.6.0 Command Deck release package

**Status:** Prepared for review, deployment, and release publication.

## What changes

Jarvis v0.6.0 establishes a clear product boundary between Discord and the
local Command Deck. Discord remains the fast, contextual surface for crew
interactions. The Command Deck becomes the primary operator surface for
configuration, monitoring, previews, audit, and complex administration.

The first complete operator workflow is one-off MuthaShip broadcasting. An
authorized local operator selects an allowlisted destination by friendly name,
composes up to 1,500 characters, previews the exact public card, then confirms
or cancels. Confirmation is short-lived and single-use. Failed Discord delivery
keeps the draft retryable. Logs retain operation, destination, time, and outcome
only, never broadcast content.

Discord `/post` remains the emergency and mobile fallback. Both surfaces reuse
the same `DelegatedPostService`, so safety and delivery behavior do not drift.

## Release checklist

- [ ] Back up the stopped production SQLite database and WAL state.
- [ ] Verify `ADMIN_CONSOLE_ENABLED=true` and a non-empty
      `ADMIN_CONSOLE_TOKEN` on the local host.
- [ ] Confirm the configured Discord channel allowlist contains only approved
      broadcast destinations.
- [ ] Run the complete test, build, lint, format, documentation, audit, and
      diff gates.
- [ ] Deploy the reviewed merge and verify `/status` reports Jarvis 0.6.0 and
      the production merge SHA.
- [ ] Re-register commands and confirm `/post` remains available.
- [ ] Open the Command Deck and verify channel names appear without raw IDs.
- [ ] Preview, cancel, and send a bounded test broadcast to the configured test
      channel.
- [ ] Repeat confirmation and verify no duplicate Discord post is created.
- [ ] Simulate a failed delivery and verify the draft remains retryable.
- [ ] Confirm audit logs contain no message content, token, or secret.
- [ ] Rehearse rollback with a disposable database copy before tagging.

## Rollback

Stop Jarvis cleanly, restore the pre-v0.6 SQLite backup and WAL state, deploy the
previous release, rebuild, re-register commands, and verify status plus the
Discord `/post` fallback. The Command Deck workflow adds no Discord permissions
and no database schema, so rollback does not require data conversion.
