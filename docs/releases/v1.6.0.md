# Jarvis v1.6.0: Sites Command Deck

Release candidate for the working tree. A maintainer tags `v1.6.0` and
deploys after this package merges and the operator smoke checklist passes.

## Shipped

- Private Sites Command Deck as the documented remote operator entry:
  read-only live snapshot when the Sites read path is configured, bounded
  Settings controls when the write access code is supplied, and six operator
  areas with honest sample, live, and unavailable states.
- Authenticated local Command Deck API with a content-free projection,
  separate read and write tokens, exact HTTPS origin allowlist, freshness,
  replay defense, rate limiting, and metadata-only audit.
- Previewed, confirmed, idempotent, and rollback-capable configuration
  controls for allowlisted broadcasts, feature flags, and RSS feeds.
- Shared SQLite open/close ownership, backup/restore rehearsal, and truthful
  provider availability in health snapshots.
- Executable shipped-feature, platform-recovery, Discord-journey, and
  Command Deck cutover verification with sanitized local receipts.

## Boundaries

- Jarvis remains a single-process Node.js runtime with SQLite. Sites never
  receives Discord, AI-provider, GitHub, RSS, Sleeper, or admin tokens.
- The localhost Command Deck at `http://127.0.0.1:8787` and Discord commands
  remain the operational fallback.
- This repository does not host the private Sites URL. The operator publishes
  that owner-only surface and records the URL outside source control.
- Economy, entertainment delivery, and Discord support tickets remain
  foundation-only. They are not user-facing v1.6 products.
- Live Discord registration, mobile rendering, and production identity after
  deploy remain operator smoke obligations. Automated matrices are not a
  substitute for `/status` on the ship computer.

## Operator enablement

1. Deploy this revision and set `JARVIS_VERSION=1.6.0` plus commit identity.
2. Keep `ADMIN_CONSOLE_HOST=127.0.0.1`. Enable the console and generate
   distinct 32+ character read and write tokens.
3. Publish the Sites project owner-only. Set Jarvis
   `COMMAND_DECK_API_ALLOWED_ORIGINS` to that exact HTTPS origin.
4. Set Sites `COMMAND_DECK_API_BASE_URL`, `COMMAND_DECK_READ_TOKEN`, and
   `COMMAND_DECK_PAGE_ORIGIN`. Never put the write token in Sites config.
5. Run `npm run command-deck-cutover:verify`, then confirm Live identity,
   unauthorized, stale, offline, preview/cancel/rollback, and localhost
   fallback against disposable targets.
6. Re-register Discord commands only if the command contract changed. v1.6.0
   does not add a new slash command.

## Rollback

Stop using the Sites URL. Use `http://127.0.0.1:8787` or Discord. Clear
`COMMAND_DECK_API_TOKEN` and `ADMIN_CONSOLE_TOKEN` or the allowed origin,
restart Jarvis, and restore the previous tagged revision if needed.
