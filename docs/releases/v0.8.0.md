# Jarvis v0.8.0 Connected Systems release

**Status:** Release candidate prepared for deployment and publication.

## What changed

Jarvis v0.8.0 establishes the Connected Systems foundation. Read-only provider
integrations share one bounded contract for readiness, health, capability, and
safe failure reporting. The release also adds administrator-only
`/feature-request preview|confirm|cancel`, which creates a labeled GitHub issue
in the configured repository without granting Jarvis issue, pull-request, or
repository-management write access.

The existing Sleeper Fantasy Football and GitHub read-only integrations remain
allowlisted and independently configurable. No provider may write to an
external system without a separately reviewed capability and explicit operator
approval.

## Release checklist

- [ ] Back up the production SQLite database and WAL state.
- [ ] Run tests, build, lint, format, documentation, audit, and diff gates.
- [ ] Deploy the reviewed tag, register commands, and start exactly one Jarvis process.
- [ ] Verify `/status` reports Jarvis 0.8.0 and the deployed commit.
- [ ] Verify `/feature-request preview` is private and confirmation is required.
- [ ] Verify provider readiness contains no secrets or raw credentials.
- [ ] Verify Sleeper and GitHub remain read-only and unavailable-safe.
- [ ] Rehearse rollback with a disposable database copy before publication.

## Boundaries

Provider credentials remain local configuration. GitHub repository and owner are
fixed by configuration. Feature-request content is bounded, mention-neutralized,
and labeled for backlog triage. The provider contract does not authorize
arbitrary URLs, repository writes, Discord server management, or autonomous
learning from conversation content.

## Rollback

Stop Jarvis, restore the pre-0.8 SQLite backup and WAL state, deploy the previous
release, register commands, and verify runtime identity plus Command Deck health.
